# Изменения TestBall QA

Версии нумеруются по [SemVer](https://semver.org/lang/ru/): `МАЖОРНАЯ.МИНОРНАЯ.ПАТЧ`.

- **Патч** (1.1.0 → 1.1.1) — исправления. Обновляться можно сразу, схема базы не меняется или меняется только добавлением.
- **Минорная** (1.1 → 1.2) — новые возможности. Миграции только добавляют таблицы и колонки; API `/api/v1` обратно совместим.
- **Мажорная** (1.x → 2.0) — несовместимые изменения. Что сделать до обновления, написано в разделе версии.

Перескакивать через версии можно: миграции всех промежуточных версий применятся по порядку. Как обновляться — [docs/UPGRADE.md](docs/UPGRADE.md).

## [1.1.0] — не выпущена

### Новое

- **Тест-кейсы:** структурные шаги с ожидаемым результатом у каждого шага, теги, пользовательские поля (текст, число, список, дата, флажок, пользователь) у кейсов, багов и прогонов.
- **Прогоны:** результат и фактический результат по каждому шагу, вложения к шагу.
- **Отчёты** по прогону и тест-плану в PDF и Excel.
- **Требования и трассировка:** требования (вручную или импортом из CSV/Jira) связываются с кейсами; покрытие по последним результатам, баги по требованию, матрица трассировки в CSV, требования в карточке кейса, перенос при экспорте и импорте проекта.
- **Автотесты:** приём `allure-results` (повторы, flaky, параметры, шаги, вложения); автотест сам связывается с ручным кейсом по номеру в названии (`@LK-12`), тегу Playwright или метке Allure.
- **Публичный API:** токены с правами `results` / `read` / `write`, сроком действия и лимитом запросов; префикс версии `/api/v1`.
- **Поиск** по кейсам, багам и прогонам (Ctrl+K), фильтры и постраничная выдача на сервере.
- **Журнал аудита** с выгрузкой в CSV; **корзина** для кейсов, прогонов и багов; удалённые проекты хранятся 30 дней и восстанавливаются.
- **Лицензия:** подписанные ключи (число мест, срок, подписка на обновления, привязка к адресу), ввод ключа в интерфейсе, предупреждения об окончании, бесплатная редакция без ключа.
- **Свои роли и разрешения:** 16 разрешений вместо «тестировщик может всё»; администратор создаёт роли («Тест-менеджер», «Автоматизатор») и выдаёт их глобально или в проекте; матрица разрешений; место в лицензии считается по разрешениям роли.
- **Персональные данные (152-ФЗ):** ссылка на политику и согласие при регистрации, выгрузка всех данных пользователя по запросу, обезличивание с сохранением истории работы, автоматическое стирание старых IP-адресов в журнале; документ «Персональные данные» для оператора.
- **Безопасность входа:** двухфакторная аутентификация (TOTP) с резервными кодами и политикой «по желанию / всем / администраторам»; политика паролей (длина, виды символов, запрет популярных, срок действия, история); смена пароля от администратора при первом входе; тайм-аут неактивности и лимит сессий; «Безопасность» вверху страницы — пароль, 2FA, активные сессии; администратор сбрасывает 2FA и завершает сессии пользователя.
- **Параметры и data-driven кейсы:** таблица параметров у кейса или общий набор данных проекта, `{{имя}}` в шагах; в прогоне — отдельная отметка по каждому набору с подставленными значениями, итог по наборам, снимок наборов в прогоне, итоги наборов в отчёте, перенос при экспорте проекта.
- **Ревью кейсов:** статус «На ревью», отправка выбранным рецензентам, утверждение всеми или возврат на доработку с комментарием, фильтр «Мне на ревью», новое разрешение «Проводить ревью», режим проекта «Готов только после ревью».
- **Общие шаги:** блок шагов вставляется в кейсы ссылкой, правка блока сразу видна во всех кейсах, в прогоне и отчётах шаги раскрываются; «Развернуть» превращает ссылку в копию; перенос при экспорте проекта.
- **Шаблоны тест-кейсов и багов:** выбор шаблона в форме создания, шаблон по умолчанию, «Сохранить как шаблон», управление во вкладке «Настройки», перенос при экспорте проекта.
- **Массовые действия с кейсами:** статус, приоритет, теги и пользовательские поля сразу у выбранных кейсов, удаление выбранных в корзину.
- **Перезапуск упавших:** кнопка на странице прогона создаёт новый прогон из упавших и заблокированных кейсов на новой сборке, с прежними исполнителями и ссылкой на исходный прогон.
- **Предрасчёт аналитики:** вкладка открывается мгновенно из заранее посчитанных данных, пересчёт идёт в фоне; кнопка «Пересчитать».
- **Очередь фоновых задач** в PostgreSQL: вебхуки, задачи в трекере, синхронизация и уборка переживают перезапуск, повторяются при ошибках и при нескольких репликах выполняются один раз; упавшие задачи видны администратору и повторяются кнопкой.
- **Мониторинг:** метрики Prometheus (`/metrics` по токену), журнал в JSON с номером каждого запроса, медленные запросы к базе в журнале, код запроса в сообщении об ошибке; дашборд Grafana, правила оповещений и ServiceMonitor для Helm.
- **Документация и справка:** руководство пользователя, руководство администратора, план пилота; кнопка «Справка» открывает всю документацию прямо в приложении, без доступа в интернет.
- **Администрирование:** страница «Лицензия и система» (лицензия, версия, сборка, база, история обновлений).

### Изменено

- `GET /api/state` возвращает только список проектов и пользователей; данные проекта — `GET /api/projects/:key/state`. Кейсы в нём без текста шагов, полный кейс — `GET /api/projects/:key/cases/:num`. Скриптам, читавшим `/api/state` целиком, нужно перейти на новые запросы (docs/API.md).
- Живые обновления приходят только по проектам, к которым у пользователя есть доступ.
- Удаление проекта — только администратор, с вводом ключа проекта.
- Токены, созданные до 1.1.0, получают право `results`: работают как раньше.
- **Роли:** разработчик теперь может переводить баги по статусам («Взять в работу», «Исправлен»). Полная роль в проекте теперь занимает полное место в лицензии, даже если глобальная роль просмотровая.
- **Пароли:** популярные пароли и пароль с логином больше не принимаются (действующие пароли не затрагиваются). Пароль, выданный администратором, теперь нужно сменить при первом входе (`PASSWORD_CHANGE_ON_RESET=false` — как раньше). Кнопка «Пароль» вверху страницы стала «Безопасность».
- **Лицензии:** без ключа теперь действует бесплатная редакция — 5 полных мест (раньше — без ограничений). Пользователей сверх лимита это не отключает, но новых тестировщиков и администраторов не добавить, пока не введён ключ. `LICENSE_FULL_SEATS` и `LICENSE_VIEW_SEATS` теперь только уменьшают лимиты лицензии.

### Исправлено

- Глобальный поиск открывается по ⌘K / Ctrl+K и при русской раскладке; на Mac в подсказке — ⌘K.
- Исполнителем в прогоне можно назначить участника со своей ролью, если у роли есть право «Выполнять прогоны» (раньше — только встроенного «Тестировщика»).
- Длинные слова без пробелов в названиях переносятся и не выталкивают кнопки за край таблицы (корзина, требования, задачи).
- Название длиннее лимита (500 символов у кейсов, багов и требований, 300 у планов, прогонов и запусков) — ошибка `400`, а не молчаливая обрезка.
- Вебхуки, CI и трекер вместо «fetch failed» пишут причину: адрес не найден, соединение отклонено, просроченный сертификат и т. п.
- Оценка нестабильности автотеста не учитывает смены результата, пока запусков меньше `FLAKY_MIN_RUNS`: по двум запускам больше не выходит «100%».

### Производительность

- Проект на 50 000 кейсов и 1 000 000 результатов: открытие ~1,3 с, поиск ~5 мс, аналитика ~0,8 с (docs/PERFORMANCE.md).

### Обновление с 1.0.x

Миграции 012–030 применятся автоматически при запуске. На большой базе (сотни тысяч результатов) первый запуск займёт несколько минут: строятся поисковые индексы. Сделайте резервную копию перед обновлением.

## [1.0.0] — 2026-11-14

Первая версия: проекты, тест-кейсы с папками и версиями, чек-листы, тест-планы, ручные прогоны, баги, автотесты (Playwright, JUnit XML), интеграции с трекерами и CI, вебхуки, аналитика, роли, единый вход (OIDC, LDAP, Kerberos), языковая модель, Docker Compose и Helm.
