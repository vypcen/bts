## Общие правила

**Адрес.** Все пути ниже указаны от адреса сервера, например `https://sports.fxtun.ru/api/state`.

**Формат.** Запросы и ответы в JSON. У запросов `POST`, `PATCH` и `DELETE` должен быть заголовок `Content-Type: application/json`, даже если тело пустое (`{}`). Без него сервер ответит `415`. Это защита от подделки запросов с чужих сайтов. Единственное исключение — загрузка файлов, см. [«Вложения»](#вложения).

**Размер тела.** До 200 КБ. Для `/api/projects/:key/autoruns/*` — до 10 МБ, потому что результаты автотестов приходят пачками со стектрейсами.

**Строки.** Сервер обрезает пробелы по краям и молча укорачивает слишком длинные значения до предела, указанного у поля. Поле, пришедшее не строкой, считается пустым.

**Идентификаторы.** У сущностей внутри проекта есть номер (`num`) и составной ID для людей:

| Сущность | ID | В пути запроса |
|---|---|---|
| Тест-кейс | `LK-12` | `/cases/12` |
| Тест-прогон | `LK-R3` | `/runs/3` |
| Баг | `LK-B7` | `/bugs/7` |
| Запуск автотестов | `LK-A5` | `/autoruns/5` |

В путях всегда передаётся номер, а не составной ID. Ключ проекта (`:key`) пишется заглавными буквами: `LK`.

**Ошибки.** При ошибке сервер возвращает JSON `{"error": "текст для человека"}` с одним из кодов:

| Код | Когда |
|---|---|
| 400 | Неверные данные: не заполнено обязательное поле, неизвестное значение, некорректный JSON |
| 401 | Нет сессии или токена (`Войдите в систему`), неверный логин или пароль |
| 403 | Роли не хватает прав (разработчик что-то меняет, не-админ вызывает `/api/admin`); токеном обращаются не к API автотестов; заблокированный пользователь входит |
| 404 | Нет проекта, сущности или маршрута. Проект, к которому у пользователя нет доступа, тоже отвечает `404` |
| 409 | Конфликт: логин или ключ проекта заняты, прогон закрыт, недопустимый переход статуса бага |
| 413 | Файл или пачка результатов слишком большие |
| 415 | Нет `Content-Type: application/json` |
| 429 | Слишком много попыток входа, регистраций, запросов к модели или открытых потоков событий |
| 500 | Внутренняя ошибка, подробности в логах сервера |
| 503 | Сервер перегружен проверкой паролей (повторите через минуту); локальная модель недоступна |
| 502, 503, 504 | Только запросы к локальной модели: модель вернула ошибку или неверный формат (`502`), не подключена, не скачана или занята (`503`), не ответила вовремя (`504`) |

**Частичное обновление.** `PATCH` кейса, прогона, бага и запуска автотестов меняет только присланные поля, остальные остаются прежними. Исключение — `PATCH` проекта, см. ниже.

## Авторизация

Есть два способа:

1. **Сессия (cookie).** Ей пользуется интерфейс. После `login` или `register` сервер ставит cookie `tb_session` (HttpOnly, 30 дней), и её нужно отправлять со всеми запросами. Даёт доступ ко всему API.
2. **Токен.** Им пользуются скрипты и CI. Передаётся заголовком `Authorization: Bearer tb_...`. Создаётся во вкладке «Автотесты» → «Подключить автотесты» или запросом [`POST /api/tokens`](#токены). Токен умеет **только** отправлять результаты: `POST /api/projects/:key/autoruns`, `POST …/autoruns/:num/results`, `POST …/results/:rid/attachments` и `PATCH …/autoruns/:num`. Любой другой запрос, в том числе чтение и удаление запусков, вернёт `403`: утёкший токен не откроет данные и не сотрёт историю. У токена те же права, что у его владельца: те же проекты и та же роль. Запуски, созданные токеном, записываются на владельца.

Заблокированный пользователь не проходит ни по сессии, ни по токену: на любой запрос вернётся `401`.

### `POST /api/auth/register`

Регистрация. Сразу выполняет вход (ставит cookie).

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `login` | string | да | 3–32 символа: латинские буквы, цифры, `.`, `_`, `-`. Приводится к нижнему регистру |
| `name` | string | да | Имя для отображения, до 100 символов |
| `password` | string | да | 8–200 символов |
| `setupCode` | string | только для первого | Код установки из логов сервера (или `SETUP_CODE` из `.env`) |

Ответ `201`: `{"user": {"login": "ivanov", "name": "Иван Иванов", "role": "developer"}}`. Если логин занят — `409`.

Новый пользователь получает роль `developer` и не видит ни одного проекта, пока админ не выдаст доступ. Самый первый пользователь в пустой базе становится `admin`, но только с верным `setupCode`, иначе `403`. При `REGISTRATION=closed` регистрация отвечает `403`: учётные записи создаёт админ ([`POST /api/admin/users`](#post-apiadminusers)). Логин из `ADMIN_LOGIN` занять регистрацией нельзя (`403`). Не больше 5 регистраций в час с одного адреса и 30 в час всего, сверх — `429`.

### `POST /api/auth/login`

| Поле | Тип | Обяз. |
|---|---|---|
| `login` | string | да |
| `password` | string | да |

Ответ `200`: `{"user": {"login", "name", "role"}}` и cookie сессии. Неверная пара — `401`. Пользователь заблокирован — `403`. Ответ `429` после 15 минут, за которые набралось 10 неудачных попыток для этого логина с этого адреса, 30 с этого адреса по любым логинам или 50 для этого логина с любых адресов.

### `POST /api/auth/logout`

Тело `{}`. Удаляет сессию. Ответ: `{"ok": true}`.

### `GET /api/auth/me`

Кто вошёл. Работает и без входа. Ответ: `{"user": {"login", "name", "role"}}`, а без входа — `{"user": null, "setup": false, "registration": "open"}`: `setup: true` — пользователей ещё нет и нужен код установки, `registration` — `open` или `closed`.

### `POST /api/auth/password`

Сменить свой пароль. Тело: `{"current": "старый", "password": "новый, 8–200 символов"}`. Неверный текущий пароль — `403`, не больше 10 попыток за 15 минут. Все остальные сессии пользователя закрываются, текущая остаётся. Ответ: `{"ok": true}`.

## Роли и доступ к проектам

| Роль | `role` | Что может |
|---|---|---|
| Тестировщик | `tester` | Всё в своих проектах: читать, создавать, менять, удалять (в том числе сам проект). Создавать проекты и токены. Не может управлять пользователями и доступами |
| Разработчик | `developer` | Читать свои проекты и писать [комментарии](#комментарии). Любой другой `POST`, `PATCH`, `PUT`, `DELETE` внутри проекта, создание проекта и токена — `403` |
| Администратор | `admin` | Всё во всех проектах без добавления в участники, плюс раздел [«Пользователи»](#пользователи-админ) |

**Свои проекты** — те, в участники которых пользователя добавил админ. Проект, созданный тестировщиком, сразу становится его проектом. К чужому проекту любой запрос отвечает `404`, как будто проекта нет, а в `/api/state` его данных нет совсем.

Если админа не осталось или он потерял доступ, задайте `ADMIN_LOGIN=<логин>` в `.env` сервера и перезапустите его: этот пользователь станет админом и будет разблокирован.

### `GET /api/events`

Поток [Server-Sent Events](https://developer.mozilla.org/ru/docs/Web/API/Server-sent_events). Нужна сессия. Когда кто-то меняет данные, приходит событие:

```
event: change
data: {"type":"bugs","at":1761040000000}
```

`type` — что изменилось: `users`, `projects`, `cases`, `runs`, `bugs`, `attachments`, `autoruns`. Сами данные в событие не входят: получив его, перечитайте `/api/state` или нужный ресурс. Каждые 25 секунд сервер шлёт комментарий-пинг, чтобы соединение не закрывалось.

## Проекты

### `POST /api/projects`

Только `tester` и `admin`. Создатель сразу становится участником проекта.

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `key` | string | да | 2–6 латинских букв, приводится к верхнему регистру. Изменить потом нельзя |
| `name` | string | да | До 200 символов |
| `desc` | string | нет | До 2000 символов |

Ответ `201`: `{"id": "LK"}`. Ключ занят — `409`.

### `PATCH /api/projects/:key`

| Поле | Тип | Обяз. |
|---|---|---|
| `name` | string | да |
| `desc` | string | нет |

В отличие от остальных `PATCH`, здесь **не** частичное обновление: `name` обязателен, а не присланное `desc` станет пустым. Ответ: `{"ok": true}`.

### `DELETE /api/projects/:key`

Удаляет проект со всеми кейсами, прогонами, багами, запусками автотестов и файлами. Может любой `tester` — участник проекта — и `admin`. Ответ: `{"ok": true}`.

## Тест-кейсы

### `POST /api/projects/:key/cases`

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `kind` | string | нет | `case` — тест-кейс (по умолчанию), `checklist` — чек-лист |
| `title` | string | да | До 500 символов |
| `priority` | string | да | `critical`, `high`, `medium`, `low` |
| `status` | string | да | `draft`, `ready`, `deprecated` |
| `pre` | string | нет | Предусловия |
| `steps` | string | нет | Шаги, обычный текст. У чек-листа — пункты, по одному в строке |
| `expected` | string | нет | Ожидаемый результат |
| `folder` | number \| null | нет | id папки этого проекта, иначе `400`. `null` или не указано — в корне проекта |

Ответ `201`: `{"id": "LK-12", "num": 12}`.

**Чек-лист** — тест-кейс со списком коротких проверок вместо шагов. Сервер очищает пункты: убирает пустые строки, нумерацию (`1.`, `2)`), маркеры (`-`, `•`, `[ ]`) и повторы. Нужен хотя бы один пункт, не больше 200, каждый до 500 символов. `pre` и `expected` у чек-листа не хранятся. В прогоне пункты отмечаются по отдельности, см. [`PATCH …/results/:case`](#patch-apiprojectskeyrunsnumresultscase).

### `POST /api/projects/:key/cases/:num/check`

Отметить пункт чек-листа выполненным прямо в чек-листе, без прогона. Тело: `{"item": "текст пункта", "done": true}`; `done: false` снимает отметку, `{"reset": true}` снимает все. Только тестировщик и админ. У тест-кейса — `400`, пункта с таким текстом нет — `404`. Дата изменения чек-листа не меняется. Ответ: `{"ok": true}`.

Отметки приходят в `GET /api/state` в поле кейса `checked`: `{"Вход работает": {"by": "ivanov", "at": "2026-10-25T10:07:00Z"}}`. Они не связаны с прогонами: результат проверки сборки и его история хранятся в прогоне.

### `PATCH /api/projects/:key/cases/:num`

Те же поля, все необязательные. Например, сменить только статус: `{"status": "deprecated"}`. `"folder": null` переносит кейс в корень проекта, без поля `folder` кейс остаётся в своей папке. Ответ: `{"ok": true}`.

### `DELETE /api/projects/:key/cases/:num`

Удаляет кейс вместе с его результатами в прогонах. Ответ: `{"ok": true}`.

### `POST /api/projects/:key/cases/move`

Переместить несколько кейсов в папку. Тело: `{"nums": [12, 15], "folder": 4}`, `"folder": null` — в корень проекта. Ответ: `{"moved": 2}` — сколько кейсов действительно поменяли папку.

## Импорт и экспорт тест-кейсов

Формат — CSV, который открывается в Excel и Google Таблицах. Колонки: `ID`, `Папка`, `Название`, `Приоритет`, `Статус`, `Предусловия`, `Шаги`, `Ожидаемый результат`, `Тип` (`Тест-кейс` или `Чек-лист`; у чек-листа пункты лежат в «Шаги»). Шаги — в одной ячейке, каждый с новой строки. Вложенные папки пишутся через ` / ` («Авторизация / Вход»).

### `GET /api/projects/:key/cases/export`

CSV-файл с кейсами проекта: UTF-8 с BOM, разделитель `;` (так его без настроек открывает Excel в русской локали). Доступно всем участникам проекта, в том числе разработчикам.

| Параметр | Описание |
|---|---|
| `folder` | `all` (по умолчанию) — все кейсы; `none` — кейсы без папки; номер папки — папка вместе с подпапками |
| `template=1` | Пустой шаблон: заголовки и одна строка-пример |

Ячейки, начинающиеся с `=`, `+`, `-`, `@`, выгружаются с апострофом в начале, чтобы Excel не выполнил их как формулу. При импорте апостроф снимается.

### `POST /api/projects/:key/cases/import`

Тело: `{"csv": "содержимое файла", "dryRun": true}`, до 5 МБ и 5000 строк. Только тестировщик и админ.

Разделитель (`;`, `,` или табуляция) определяется по строке заголовков. Заголовки узнаются по-русски и по-английски, как в выгрузках TestRail и Qase (`Title`, `Section`, `Priority`, `Preconditions`, `Steps`, `Expected Result`), регистр не важен. Обязательна только колонка «Название». Приоритет и статус принимаются подписями («Высокий», «Готов»), ключами API (`high`, `ready`) и словами других систем (`Highest`, `Normal`, `Minor`, `Actual`…). Вложенные разделы TestRail через `>` тоже понимаются.

- Строка с ID этого проекта (`LK-12`) **обновляет** кейс. Меняются только колонки, которые есть в файле; пустая ячейка «Папка» переносит кейс в корень.
- Строка без ID, с ID другого проекта или с несуществующим номером **создаёт** новый кейс (по умолчанию приоритет «Средний», статус «Черновик»).
- Недостающие папки по пути создаются.

С `dryRun: true` ничего не записывается. Ответ:

```json
{"summary": {"rows": 120, "create": 100, "update": 15, "unchanged": 5, "folders": 3}, "errors": [{"line": 7, "error": "Пустое название"}], "errorCount": 1}
```

`line` — номер строки в файле с учётом многострочных ячеек. Без `dryRun` файл применяется одной транзакцией: при любой ошибке ничего не импортируется, ответ `400` с теми же `errors`. Удачный импорт отвечает `{"summary": {…}}`.

## Папки тест-кейсов

Дерево папок внутри проекта. В одной папке не может быть двух подпапок с одинаковым названием (`409`), в корне тоже. Папки приходят в [`/api/state`](#get-apistate) в поле `folders`, у кейса папка в поле `folder`.

### `POST /api/projects/:key/folders`

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `name` | string | да | До 200 символов |
| `parent` | number \| null | нет | id родительской папки. `null` или не указано — в корне |

Ответ `201`: `{"id": 4}`.

### `PATCH /api/projects/:key/folders/:id`

Те же поля, оба необязательные: переименовать, перенести или то и другое. Перенос папки в саму себя или в свою подпапку — `400`. Ответ: `{"ok": true}`.

### `DELETE /api/projects/:key/folders/:id`

Удаляет только саму папку: её кейсы и подпапки поднимаются на уровень выше (в родительскую папку или в корень). Если там уже есть папка с тем же названием, что у одной из подпапок, — `409`, ничего не меняется. Ответ: `{"ok": true}`.

## Тест-прогоны

Ручные прогоны: набор кейсов, проверяемый на конкретной сборке.

### `POST /api/projects/:key/runs`

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `title` | string | да | До 300 символов |
| `caseNums` | number[] | да | Номера кейсов проекта, хотя бы один. Чужие и несуществующие номера пропускаются |
| `build` | string | нет | Сборка или версия, до 200 символов |
| `env` | string | нет | Окружение, до 500 символов |

Ответ `201`: `{"num": 3}`. Все кейсы попадают в прогон со статусом `untested`.

### `PATCH /api/projects/:key/runs/:num`

| Поле | Тип | Описание |
|---|---|---|
| `title`, `build`, `env` | string | Как при создании |
| `state` | string | `open` или `closed` |

Ответ: `{"ok": true}`.

### `DELETE /api/projects/:key/runs/:num`

Ответ: `{"ok": true}`.

### `POST /api/projects/:key/runs/:num/cases`

Добавить кейсы в открытый прогон. Тело: `{"caseNums": [14, 15]}`. Кейсы, которые уже есть в прогоне, пропускаются. Ответ: `{"added": 2}`. Если прогон закрыт — `409`.

### `PATCH /api/projects/:key/runs/:num/results/:case`

Результат кейса в прогоне. `:case` — номер кейса.

| Поле | Тип | Описание |
|---|---|---|
| `result` | string | `untested`, `passed`, `failed`, `blocked`, `skipped` |
| `comment` | string | Комментарий |
| `item` | string | Только для чек-листа: текст пункта, которому ставится `result`. `untested` снимает отметку |

У чек-листа отмечаются пункты: `{"item": "Вход работает", "result": "failed"}`. Итог считается сам: упал хоть один пункт — `failed`, затем `blocked`; пока есть неотмеченные — `untested`; все отмечены — `passed` (или `skipped`, если все пропущены). Прислать `result` без `item` для чек-листа нельзя — `400`. Пункта с таким текстом нет (например, его только что переименовали) — `404`.

Исполнитель и время записываются, только когда меняется `result`. Возврат в `untested` их очищает. Если прогон закрыт — `409`. Ответ: `{"ok": true}`.

| `severity` | string | да | `blocker`, `critical`, `major`, `minor` |

Ответ: `{"ok": true}`.

## Вложения

Файл отправляется «сырым» телом запроса, без multipart и JSON.

**Заголовки загрузки:**

| Заголовок | Обяз. | Описание |
|---|---|---|
| `X-Upload: 1` | да | Без него сервер ответит `415` |
| `Content-Type` | да | MIME-тип файла, например `image/png` |
| `X-Filename` | нет | Имя файла, закодированное через `encodeURIComponent`. По умолчанию `file` |
| `Content-Length` | да | Размер. `curl --data-binary` и `fetch` ставят его сами |

Максимальный размер — `MAX_UPLOAD_MB` из `.env` сервера, по умолчанию 20 МБ. Больше — `413`. Ответ на загрузку `201`: `{"id": "<uuid>"}`.

| Запрос | Куда прикладывается |
|---|---|
| `POST /api/projects/:key/bugs/:num/attachments` | К багу |
| `POST /api/projects/:key/runs/:num/results/:case/attachments` | К результату кейса `:case` в прогоне `:num` |
| `POST /api/projects/:key/autoruns/:num/results/:rid/attachments` | К результату автотеста. `:rid` — id из ответа [`POST …/results`](#post-apiprojectskeyautorunsnumresults). Работает с токеном |

```sh
curl -X POST "$URL/api/projects/LK/bugs/7/attachments" \
  -b "tb_session=…" -H "X-Upload: 1" -H "Content-Type: image/png" \
  -H "X-Filename: $(node -p 'encodeURIComponent("скрин 1.png")')" \
  --data-binary @"скрин 1.png"
```

### `GET /api/attachments/:id`

Скачать файл. Нужна сессия: с токеном не работает. Файл из недоступного проекта отвечает `404`. Картинки (png, jpeg, gif, webp) и `text/plain` открываются в браузере, остальное отдаётся на скачивание.

### `DELETE /api/attachments/:id`

Тело `{}`. Только `tester` и `admin` с доступом к проекту файла. Ответ: `{"ok": true}`.

## Автотесты

Запуск автотестов — «папка» с результатами. Порядок работы скрипта, который отправляет результаты:

1. `POST /autoruns` — создать запуск и получить его номер.
2. `POST /autoruns/:num/results` — отправлять результаты пачками по ходу тестов или одной пачкой в конце.
3. `POST /autoruns/:num/results/:rid/attachments` — приложить скриншоты к нужным результатам.
4. `PATCH /autoruns/:num` с `{"state": "finished"}` — завершить запуск.

Все пути ниже начинаются с `/api/projects/:key`. Отправка результатов (шаги 1–4 выше) работает и с сессией, и с токеном; чтение и удаление — только с сессией. Готовые клиенты — [`scripts/playwright-reporter.js`](../scripts/playwright-reporter.js) (Playwright) и [`scripts/report.js`](../scripts/report.js) (JUnit XML).

### `POST /api/projects/:key/autoruns`

Создать запуск. Он сразу появляется во вкладке «Автотесты» со статусом «Идёт».

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `title` | string | да | Название, до 300 символов |
| `scope` | string | нет | Что запускали, например проекты Playwright: `supportcd, pgw`. До 500 символов |
| `env` | string | нет | Окружение, например `RC`. До 500 символов |
| `url` | string | нет | Адрес тестируемого приложения. До 500 символов |
| `branch` | string | нет | Ветка, до 200 символов |
| `build` | string | нет | Сборка или коммит, до 200 символов |

В шапке запуска показываются `scope`, `env` и `url`. `branch` и `build` видны в «Параметрах» запуска и подставляются в баг, заведённый из упавшего теста.

Ответ `201`: `{"num": 5, "id": "LK-A5"}`. Нет проекта — `404`.

### `POST /api/projects/:key/autoruns/:num/results`

Отправить результаты. Тело: `{"results": [ … ]}`, от 1 до 1000 элементов.

| Поле результата | Тип | Обяз. | Описание |
|---|---|---|---|
| `name` | string | да | Название теста, до 1000 символов |
| `status` | string | да | `passed` — прошёл, `failed` — не прошла проверка, `broken` — ошибка в самом тесте или окружении (таймаут, исключение), `skipped` — пропущен |
| `suite` | string | нет | Набор: файл, класс, describe. До 500 символов |
| `file` | string | нет | Путь к тесту, например `tests/login.spec.ts:12` |
| `durationMs` | number | нет | Длительность в миллисекундах |
| `message` | string | нет | Короткий текст ошибки, до 5000 символов. Показывается в списке |
| `details` | string | нет | Стектрейс и подробности, до 50 000 символов |
| `steps` | Step[] | нет | Шаги теста, см. ниже |

**Как узнаётся тест.** Ключ теста — `suite › name`, а если набора нет, просто `name`. При первой встрече тест заводится в реестре проекта («Все автотесты»), дальше результаты привязываются к нему. Переименованный тест заведётся как новый.

**Повторы.** Если в одном запуске результат того же теста приходит снова, например после перезапуска упавшего, он заменяет прежний. Если тест встретился дважды в одном запросе, берётся последний.

**Шаг (`Step`):**

| Поле | Тип | Описание |
|---|---|---|
| `title` | string | Название шага, обязательно. Шаги без названия отбрасываются |
| `status` | string | `passed`, `failed`, `skipped`. Неизвестное значение считается `passed` |
| `durationMs` | number | Длительность |
| `error` | string | Текст ошибки упавшего шага, до 2000 символов |
| `steps` | Step[] | Вложенные шаги |

Не больше 300 шагов на тест вместе с вложенными и не глубже 8 уровней, лишнее отбрасывается. Шагом падения считается самый глубокий шаг со статусом `failed`, поэтому родительские шаги упавшего тоже стоит помечать `failed`. В реестр попадают названия шагов: из любого результата, если шагов там ещё нет, и из прошедшего, который их заменяет.

Пример:

```json
{
  "results": [
    {
      "suite": "[supportcd] view.test.ts",
      "name": "Проверить отображение раздела История",
      "file": "test/supportCD/view.test.ts:24",
      "status": "failed",
      "durationMs": 8120,
      "message": "expect(locator).toBeVisible() failed",
      "details": "Error: expect(locator).toBeVisible() failed\n…",
      "steps": [
        { "title": "Выполнить авторизацию", "status": "passed", "durationMs": 2100, "steps": [] },
        {
          "title": "Проверить отображение раздела История", "status": "failed", "durationMs": 5000,
          "error": "expect(locator).toBeVisible() failed",
          "steps": []
        }
      ]
    }
  ]
}
```

Ответ: `{"ids": [812]}` — id результатов в том же порядке, в каком они пришли. По ним прикладываются файлы. Ошибка в одном элементе — `400` с номером элемента: `results[3]: нужны name и status (…)`, и тогда не сохраняется вся пачка. Нет запуска — `404`.

### `PATCH /api/projects/:key/autoruns/:num`

Завершить запуск или поменять его параметры.

| Поле | Тип | Описание |
|---|---|---|
| `state` | string | `running` или `finished`. При `finished` фиксируется время окончания |
| `title`, `scope`, `env`, `url`, `branch`, `build` | string | Как при создании |

Ответ: `{"ok": true}`. Запуск, который не перевели в `finished` (например, процесс убили), так и останется «Идёт».

### `GET /api/projects/:key/autoruns/:num`

Содержимое запуска: результаты, шаги, вложения и статус каждого теста в предыдущем запуске.

```jsonc
{
  "results": [{
    "id": 812, "testId": 40, "suite": "[supportcd] view.test.ts", "name": "…", "file": "…",
    "status": "failed", "durationMs": 8120, "message": "…", "details": "…",
    "steps": [ /* Step[] */ ],
    "prev": { "status": "passed", "runNum": 4 }   // null, если тест встретился впервые
  }],
  "attachments": [{
    "id": "uuid", "pid": "LK", "bugNum": null, "resultId": null, "autoResultId": 812,
    "name": "screenshot.png", "mime": "image/png", "size": 48213, "uploadedBy": "ivanov", "created": 1761040000000
  }]
}
```

Сводка по всем запускам (статусы, счётчики, длительность) приходит в `autoruns` из [`GET /api/state`](#get-apistate).

### `DELETE /api/projects/:key/autoruns/:num`

Удаляет запуск с результатами и файлами. Тесты остаются в реестре. Ответ: `{"ok": true}`.

### `GET /api/projects/:key/autotests`

Реестр автотестов проекта. Нужна сессия.

```jsonc
{
  "tests": [{
    "id": 40, "suite": "[supportcd] view.test.ts", "name": "…", "file": "…",
    "steps": [{ "title": "Выполнить авторизацию", "steps": [] }],
    "created": 1761040000000,
    "history": [{ "status": "failed", "runNum": 5 }, { "status": "passed", "runNum": 4 }]  // последние 10, свежий первым
  }]
}
```

### `DELETE /api/projects/:key/autotests/:id`

Удаляет тест из реестра вместе с его результатами во всех запусках. Если тест снова придёт в отчёте, он заведётся заново. Нужна сессия. Ответ: `{"ok": true}`.

### Пример: отправка через curl

```sh
URL=https://sports.fxtun.ru; KEY=LK
H=(-H "Authorization: Bearer $TESTBOL_TOKEN" -H "Content-Type: application/json")

NUM=$(curl -s "${H[@]}" -X POST "$URL/api/projects/$KEY/autoruns" \
  -d '{"title":"Смоук","scope":"supportcd","env":"RC"}' | node -p 'JSON.parse(require("fs").readFileSync(0)).num')

RID=$(curl -s "${H[@]}" -X POST "$URL/api/projects/$KEY/autoruns/$NUM/results" \
  -d '{"results":[{"suite":"auth","name":"Вход","status":"failed","message":"Нет кнопки"}]}' \
  | node -p 'JSON.parse(require("fs").readFileSync(0)).ids[0]')

curl -s -X POST "$URL/api/projects/$KEY/autoruns/$NUM/results/$RID/attachments" \
  -H "Authorization: Bearer $TESTBOL_TOKEN" -H "X-Upload: 1" -H "Content-Type: image/png" \
  -H "X-Filename: screen.png" --data-binary @screen.png

curl -s "${H[@]}" -X PATCH "$URL/api/projects/$KEY/autoruns/$NUM" -d '{"state":"finished"}'
```

## Токены

Управление токенами текущего пользователя. Нужна сессия: токеном токены не создаются.

### `GET /api/tokens`

Ответ: `{"tokens": [{"id": 3, "name": "CI", "created": 1761040000000, "used": 1761040500000}]}`. `used` — время последнего запроса с токеном или `null`. Сам токен не возвращается никогда.

### `POST /api/tokens`

Тело: `{"name": "CI"}`, обязательно, до 100 символов. Только `tester` и `admin`: токен нужен, чтобы отправлять результаты, а разработчику это недоступно. Ответ `201`: `{"token": "tb_…"}`. Токен показывается только в этом ответе, в базе хранится его хэш.

### `DELETE /api/tokens/:id`

Отзывает токен: скрипты с ним сразу перестают работать. Ответ: `{"ok": true}`.

## Пользователи (админ)

Все запросы раздела — только для `admin`, остальным `403`. Свою роль и блокировку админ поменять не может, себя удалить тоже (`409`): так нельзя случайно остаться без админа.

### `GET /api/admin/users`

```json
{
  "users": [{
    "login": "petrov", "name": "Пётр Петров", "role": "developer", "blocked": false,
    "created": 1761040000000, "projects": ["BO", "LK"]
  }]
}
```

`projects` — проекты, в которые пользователь добавлен. Админу они не нужны: он видит все.

### `POST /api/admin/users`

Создать пользователя — единственный способ при `REGISTRATION=closed`.

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `login` | string | да | Как при регистрации |
| `name` | string | да | До 100 символов |
| `password` | string | да | Временный пароль, 8–200 символов |
| `role` | string | нет | `tester` (по умолчанию), `developer`, `admin` |

Ответ `201`: `{"login": "anna"}`. Логин занят — `409`. Доступ к проектам выдаётся отдельно: [`PUT …/projects`](#put-apiadminusersloginprojects).

### `PATCH /api/admin/users/:login`

| Поле | Тип | Описание |
|---|---|---|
| `role` | string | `tester`, `developer`, `admin` |
| `blocked` | boolean | `true` — заблокировать: пользователь сразу выходит из всех сессий, его токены перестают работать. `false` — разблокировать |
| `password` | string | Новый пароль, 8–200 символов. Пользователь выходит из всех сессий |

Можно прислать одно из полей. Ответ: `{"ok": true}`.

### `PUT /api/admin/users/:login/projects`

Тело: `{"projects": ["LK", "BO"]}`. Список **заменяет** прежний: проекты, которых нет в списке, у пользователя пропадут. Пустой список забирает доступ ко всем. Несуществующие ключи пропускаются. Ответ: `{"ok": true}`.

### `DELETE /api/admin/users/:login`

Удаляет пользователя, его сессии и токены. Созданные им кейсы, баги и прогоны остаются, в авторах у них будет пусто. Если нужно только закрыть доступ, лучше заблокировать. Ответ: `{"ok": true}`.

## Локальная модель

Необязательная языковая модель для подсказок (настройка — в README, часть 4). Ответ модели ничего не меняет сам: его показывают пользователю, а сохраняет он сам обычными запросами.

### `GET /api/llm/status`

Подключена ли модель и готова ли она отвечать. Нужен вход в систему.

```json
{"enabled": true, "model": "qwen2.5:3b", "ready": false, "error": "Модель qwen2.5:3b не скачана"}
```

`enabled: false` — `LLM_URL` не задан, функции с моделью выключены. Поле `error` есть только при `ready: false`.

### `POST /api/projects/:key/ai/bug-draft`

Оформить баг из черновых записей. Тело — поля формы бага: `title`, `env`, `steps`, `actual`, `expected` (нужно хотя бы одно из `title`, `steps`, `actual`). Только тестировщик и админ.

```json
{"title": "Вход — кнопка «Войти» не реагирует", "steps": "1. …
2. …", "actual": "…", "expected": "…", "severity": "major"}
```

`severity` — `null`, если модель не смогла выбрать допустимое значение.

### `POST /api/projects/:key/ai/case-draft`

Составить кейс по названию. Тело: `title` (обязательно), `pre`, `steps`, `expected` — уже написанное модель дополняет. Только тестировщик и админ. Ответ: `{"pre": "…", "steps": "…", "expected": "…"}`.

### `POST /api/projects/:key/ai/autoresults/:id/explain`

Разбор упавшего (`failed` или `broken`) автотеста: что случилось, вероятная причина, что проверить. Тело `{}`. `:id` — `id` результата из `GET /api/projects/:key/autoruns/:num`. Доступно всем участникам проекта, в том числе разработчикам. Ответ: `{"text": "…"}`. Это `POST`, а не `GET`, чтобы чужой сайт не мог запустить модель ссылкой или картинкой.

Ко всем запросам раздела: у пользователя одновременно может идти один запрос к модели и не больше 20 за 10 минут (`LLM_USER_LIMIT`), сверх — `429`.

| Запрос | Описание |
